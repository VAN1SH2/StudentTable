# StudentTable 0.5.1 — переключение дат и задания после смены недели

Дальние даты переключаются непосредственно с коротким появлением вместо прокрутки промежуточных страниц. Автоматические переходы не записывают промежуточную страницу в выбранный день. Соседние страницы и жесты сохранены. Лента не прокручивается, если выбранная дата уже полностью видна; календарное окно и страницы имеют ключи реальных дат.

Причина, воспроизводимая в тестах: импорт заменял пары, но задачи сохраняли прежний `lessonId`. При изменении ID, в том числе после перехода к следующей календарной неделе и автообновления, ежедневный экран переставал находить связанную задачу. Добавлен отдельный стабильный ключ пары и Room 7 с миграцией 6 → 7. Импорт транзакционно фиксирует старую связь, переносит ID на уникальное совпадение и сохраняет дату, ручной дедлайн, отметку выполнения, заметки и несколько напоминаний. Неоднозначные совпадения не угадываются и не превращаются в задачи всего предмета.

При запуске старые связи дополняются из кеша. Уже потерянные ID восстанавливаются без интернета, если сохранённая дата и дедлайн однозначно соответствуют началу одной пары. Без прежнего кеша и с изменённым вручную сроком информации для безопасного восстановления может не хватить: достаточно один раз выбрать пару в редакторе. Новые сохранённые ключи от ручного срока не зависят.

Проверка 08.10.2026: `:core:test :app:compileDebugKotlin` — BUILD SUCCESSFUL; 43 теста core без ошибок. `:app:testDebugUnitTest` с фильтрами DatabaseMigrationTest, StudentRepositoryTest, TaskLessonBindingsTest, LessonTaskTest, TaskSchedulingTest и ReminderPlanTest — BUILD SUCCESSFUL; 35 тестов без ошибок и пропусков. Проверены переход следующей недели в текущую для СФУ и ИРНИТУ, выбранная подгруппа, смена ID пары и предмета, ручной срок, исключение лекции/другой подгруппы/другой даты, безопасное восстановление старой связи, удаление и отмена, миграции 1/2/3/4/5/6 → 7. Room экспортировал схему 7. Версия приложения — 0.5.1, versionCode 9.

APK не создавался и приложение на телефон не устанавливалось. Жесты и плавность на телефоне пока не проверены; синхронизация переключения и ограничение прокрутки проверены компиляцией и чтением кода.

# StudentTable 0.5.0 — лента дат, задачи и несколько напоминаний

# StudentTable 0.4.1 — привязка задачи к конкретной паре

Исправлена причина дублирования задания у лекции и практики: ранее редактор использовал выбранную пару только для срока, а сохранял связь с предметом. В задаче теперь сохраняются `lessonId` и `lessonDate`; главный экран сравнивает ID занятия и дату, полное недатированное расписание — ID. При открытии редактора из практики заранее выбирается занятие именно этой карточки. Ручное изменение срока не сбрасывает связь; для общей задачи есть «Без привязки к паре».

Room обновлён с 4 до 5, миграция добавляет два nullable-поля без удаления или изменения старых задач, групп, напоминаний и настроек. Для старых задач не угадывается тип занятия по сроку: нужную пару следует один раз выбрать в редакторе и сохранить. Связь сохраняется при обычном редактировании, завершении, удалении и отмене удаления. Уведомления о задачах по-прежнему планируются по их сроку и ID.

Подготовлены регрессионные тесты отображения одной пары, даты, ручного срока, выбора из карточки и сохранения привязки; миграционные тесты расширены до версии 5 и включают переход 4 → 5 с сохранением подгрупп. По действующей просьбе пользователя сборка, тесты и APK исправления не запускались. Успешная компиляция и миграция на устройстве пока не подтверждены. Схема 5 будет экспортирована Room при следующей компиляции.
